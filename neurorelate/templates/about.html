Relational Entity-Relationship (ER) Model

NeuroRelate models unstructured document ingestion as a normalized 1-to-N relational structure. When documents are ingested, parent metadata is stored in documents, and extracted text is segmented into chunks stored in document_chunks tied by foreign keys.

Table: documents

CREATE TABLE documents (
  id INT AUTO_INCREMENT PRIMARY KEY,
  filename VARCHAR(255) NOT NULL,
  upload_date DATETIME NOT NULL,
  extracted_text LONGTEXT,
  file_size INT DEFAULT 0,
  chunk_count INT DEFAULT 0
);

Table: document_chunks

CREATE TABLE document_chunks (
  id INT AUTO_INCREMENT PRIMARY KEY,
  document_id INT NOT NULL,
  chunk_text TEXT NOT NULL,
  chunk_number INT NOT NULL,
  FOREIGN KEY (document_id) 
    REFERENCES documents(id) 
    ON DELETE CASCADE
);

Table: query_history (Telemetry & Audit)

CREATE TABLE query_history (
  id INT AUTO_INCREMENT PRIMARY KEY,
  question TEXT NOT NULL,
  answer TEXT NOT NULL,
  source_document VARCHAR(255),
  created_at DATETIME NOT NULL
);

RESTful API Reference

Method Endpoint Payload / Query Description
POST /api/documents/upload multipart/form-data file Ingests document, extracts text, chunks, and commits to RDBMS
GET /api/documents — Lists all documents with chunk counts and metadata
GET /api/documents/<id>/chunks — Returns all chunks for a specific document
DELETE /api/documents/<id> — Cascading delete of document record, chunks, and disk file
POST /api/search JSON {query, top_k, doc_id} Hybrid BM25 keyword and phrase retrieval over chunks
POST /api/chat JSON {question, doc_id, top_k} Retrieves context, invokes AI model, and saves to query history
POST /api/database/query JSON {query} Executes safe SELECT query in the live web SQL console
